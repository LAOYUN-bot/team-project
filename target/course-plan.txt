第一部分 课程概况
1.课程定位与修订背景
本修订在保留工程底座的同时，把 AI 素养、人机协作、团队工程规范、伦理安全 纳入课程主线，使实训更贴合产业现状与学生成长路径。
2.实践目标
围绕"会做工程、善用 AI、能协作、守底线"四个维度设定目标。
2.1 工程基础能力
掌握现代 Web 全栈开发：后端（Spring Boot / SSM）、前端（Vue.js）、数据库（MySQL）、版本控制（Git）。
理解 MVC 分层与职责分离，能独立完成可运行、可部署的 Web 应用。
2.2 AI 素养与智能工具应用能力
熟练使用 AI 编程助手（GitHub Copilot、Cursor、通义灵码、Claude Code 等）提升编码与调试效率，并能辨别其产出质量与局限。
理解大模型能力边界，掌握提示工程（Prompt Engineering）基本方法，能编写清晰、可复用的任务指令。
2.3 人机协作与智能应用开发能力
能调用大模型 API（兼容 OpenAI / 通义 / 文心等协议）实现问答、摘要、分类等智能功能。
理解 RAG（检索增强生成）基本思路，能基于知识库构建简易智能问答原型。
能把 AI 能力作为"功能模块"嵌入团队项目，而非把整个项目外包给 AI。
2.4 团队协作与工程规范能力
掌握团队角色分工、轻量敏捷迭代（Scrum）、代码评审、文档与例会规范。
建立"团队 AI 使用公约"：明确哪些环节可用 AI、如何标注 AI 产出、如何做人工复核。
2.5 伦理、安全与合规意识
理解数据隐私、模型偏见、提示注入、版权与开源协议等基本风险。
在项目中对敏感信息脱敏、对 AI 生成内容做人工验证与责任归属。

第二部分 个人技能实训

目标：在保留全栈工程能力的基础上，建立"AI 是生产力工具"的自觉，为团队 AI 项目打基础。
任务要求：
每个实验独立（或结对）完成，提交一份实验报告；
报告含主要步骤截图与关键代码说明；
报告末尾含总结与反思，并新增 "AI 工具使用记录"（用了哪些 AI 工具、在哪些环节、提示词要点、产出如何验证）；
严禁直接提交 AI 生成的未理解代码；教师随机抽测代码讲解。
说明：实验一的原方案包含 pom.xml / web.xml / Spring / MyBatis 等完整配置样例，技术细节仍有效，本版不再重复，重点说明目标、AI 增强与验收点；需要时可参照原方案。


实验一：搭建 Web 基础项目（Spring Boot / SSM）
目标：用 Maven / Gradle 创建 Web 项目，配置数据源，完成用户表 CRUD；用内嵌容器或 Tomcat 部署运行。
准备：JDK 17、Maven、IntelliJ IDEA、MySQL / Navicat、AI 编程助手。
步骤要点：
创建项目（推荐 Spring Boot 3.x，起步依赖 spring-boot-starter-web、mybatis-spring-boot-starter、mysql-connector-j）；
配置 application.yml 数据源；编写 Entity / Mapper / Service / Controller 分层；
用 AI 助手生成脚手架与单测，但须逐行理解并人工验证；
运行 mvn spring-boot:run 或打成 jar 部署，验证 CRUD。
实验二：前后端分离与 RESTful API
目标：后端提供 RESTful JSON 接口，前端 Vue 调用，Ajax / Axios 交互，解决跨域。
步骤要点：@RestController 暴露接口；Vue 组件 + Axios；Spring 配置 CORS；分别构建部署并联调。
AI 增强：用 AI 辅助生成 Vue 组件与接口文档（OpenAPI），但须人工核对字段与错误边界。
实验三：Git 协作开发与持续集成
目标：分支管理、Pull Request、Code Review、基础 CI。
步骤要点：git init / 分支 feature/* / git merge / 解决冲突 / 推送远程；引入 PR 模板与基础 CI（如 GitHub Actions 跑构建与测试）。
AI 增强：用 AI 做初步代码评审（PR 摘要、潜在 bug 提示），但人工评审为最终责任方。
实验四：登录、权限与 AI 安全
目标：实现登录与基于角色的访问控制（RBAC），签发 JWT；同步建立安全意识。
步骤要点：用户 / 角色 / 权限表；Shiro 或 Spring Security；密码加密（BCrypt）；JWT 签发与校验；@PreAuthorize 控制接口。
AI 安全要点：密钥与密码绝不入库明文、入库须加密；前端不裸存明文令牌；对"用户可控输入 → 模型"的链路做提示注入防护与输入校验。
实验五：LLM 应用开发与智能功能原型
目标：调用大模型 API 实现一项智能功能（如智能问答 / 摘要 / 分类），理解提示工程与 RAG 入门。
准备：申请一个兼容 OpenAI 协议的大模型 API Key（通义 / 文心 / 本地 Ollama 均可）；Python 或 Java SDK。
步骤要点：
提示工程：编写 System / User 提示，完成"给定需求 → 稳定输出"的小练习；
接口调用：用 SDK 调用对话接口，封装一个 ask(question) 函数；
RAG 入门：把一小份课程 / 项目文档切块 → 向量化 → 检索 → 拼入提示，实现"基于资料作答"；
原型：将智能功能接入实验一的项目（如"学习搭子"问答入口），产出可演示原型；
反思：记录模型答错 / 幻觉案例及应对（限定上下文、给出出处、人工兜底）。


第三部分 团队项目实训
1 团队规范
角色分工：产品经理（PM）、后端、前端、AI / 算法、测试 / 文档，每人至少承担一类并可兼任；
例会制度：每 Sprint 站会（≤15 分钟）+ 评审；例会记录进仓库 docs/；
代码规范：统一格式化、命名约定、分支模型（main / develop / feature/*）、PR 必须 ≥ 1 人评审；
文档规范：需求、设计、测试、README 齐全，目录见 5.4；
AI 使用公约：可用 AI 做检索、脚手架、单测、文案；禁止用 AI 代写整模块后不复核；所有 AI 生成代码需注释 // AI-assisted 并人工理解；关键决策（架构、安全）须人工拍板。
2 项目选题
选题来自：2026“数字马力杯”第十三届浙江省大学生服务外包创新应用大赛赛题手册 本科部分
选题原则：① 必须包含可演示的 AI 功能（调用大模型 / 规则 + 模型）；② 与专业或校园场景结合；③ 难度与 4–6 人、一学期匹配；④ 明确"哪些是团队使用的新技术"并在概要中标注。

4 成果交付标准（明确化，原方案仅有清单）
每个交付物须达到以下基线，方可进入答辩：
项目概要文件：项目简介、技术栈（标注新技术）、角色安排、进度表；
需求分析与设计文档：用例 / 用户故事、功能清单、ER / 架构图、接口说明；
原型演示（视频 3–5 分钟）：覆盖核心流程，含 AI 功能实拍；
项目源代码：可在 README 指引下本地复现运行；含 AI 使用说明；
测试文档：功能测试 + 至少 1 项 AI 安全 / 边界测试（如提示注入、幻觉）；
个人总结（每人 1 份）：本人贡献、学到什么、AI 如何参与、反思。
质量门槛：功能完整度、AI 功能可用性、代码规范、文档完备、演示效果，任一不达标需补正。

6.AI 伦理与合规要求
数据：用户数据脱敏，不上传敏感信息到公网模型；
版权：AI 生成代码 / 文案需确认许可，遵守开源协议；
责任：AI 产出须人工验证，关键决策人工负责；
透明：产品 / 文档中说明 AI 能力边界，不夸大。
