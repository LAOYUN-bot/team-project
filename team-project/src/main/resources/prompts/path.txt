# 关键约束：粒度必须到「可验证产出物」，否则人工评审可执行率不达标（难点 D-2）

## 任务
基于【用户上下文】中的目标岗位、能力差距与可用学习时长，生成一条 3–5 年的职业发展路径。

## 硬性约束
1. 必须输出 **4 到 5 个阶段**，时间轴连续覆盖 0 到 N 个月（N ∈ [36, 60]）。
2. 每个阶段必须包含：
   - `name`：阶段名（体现能力跃迁，如「工程基础夯实期」，不要用「第一阶段」这种空话）
   - `startMonth` / `endMonth`：起止月（从 0 开始计）
   - `goal`：该阶段结束时**可被检验**的状态（含具体能力或作品）
   - `skills`：本阶段主攻的技能（必须来自上下文给出的技能清单，不得自造）
   - `outputs`：**可验证产出物**，如「一个部署上线的 CRUD 项目（含 README 与测试）」
3. 阶段顺序必须符合能力依赖：先基础、后工程化、再架构/深度、最后影响力。
4. 严禁出现「多学习」「多实践」「提升综合能力」这类无法验收的表述。
5. 若用户每周可用学时为 H，阶段目标的工作量必须与 H × 阶段月数 × 4 周相匹配，不得超载。

## 输出格式（严格 JSON，不要输出任何解释文字或代码块围栏）
{
  "horizonYears": 4,
  "stages": [
    {
      "name": "工程基础夯实期",
      "startMonth": 0,
      "endMonth": 9,
      "goal": "能独立完成一个具备分层结构、含单元测试的后端服务并部署上线",
      "skills": ["Java 语言基础", "Spring Boot", "MySQL 数据库"],
      "outputs": ["一个部署上线的 CRUD 服务（含 README、接口文档与 ≥60% 单测覆盖）"]
    }
  ],
  "reasoning": ["该阶段安排依据：用户当前 Java 基础自评为中，需先补齐工程规范"]
}
