# 例会与周报留档

> 课程考核「过程表现（Sprint 周报、例会、Code Review）」占 **20%**，
> 看的是协作与规范遵守，因此每一次站会与每周周报都要留档在本目录。

---

## 一、制度

| 项 | 规定 |
|---|---|
| 站会频率 | 每 Sprint 至少 1 次站会（≤15 分钟）+ 1 次 Sprint 评审 |
| 站会内容 | 三问：上次做了什么 / 这次做什么 / 有什么阻塞 |
| 周报频率 | 每周 1 份，周五前提交 |
| 留档方式 | 站会记录与周报均提交到本目录，文件名见下 |
| 命名规范 | `Sprint<N>-例会记录.md`、`Sprint<N>-周报.md`、`Sprint<N>-评审记录.md` |

---

## 二、文件模板

```markdown

|---|------|--------|----------|--------|-----|
| 1 |      |        | FR-x.x   | 100%   | #12 |

## 二、下周计划
| # | 事项 | 负责人 | 关联需求 | 预计完成 |
|---|------|--------|----------|----------|

## 三、阻塞与风险
| # | 问题 | 影响 | 应对 | 责任人 |
|---|------|------|------|--------|

## 四、本周数据
- CI：通过 <n> 次 / 失败 <n> 次
- 合并 PR：<n> 个，平均评审轮次 <n>
- 新增测试用例：<n> 个
- 代码量变化：+<n> / -<n> 行

## 五、AI 使用情况
- 本周使用 AI 的环节：
- 发现 AI 产出问题的次数与处理：
```

| 成员 | 上次完成 | 本次计划 | 阻塞 |
|------|----------|----------|------|
|      |          |          |      |
