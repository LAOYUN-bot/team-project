# 个人总结

> 课程要求：**每人提交 1 份**（对应考核「个人贡献」25%）。
> 内容要求：**本人贡献、学到什么、AI 如何参与、反思**。

---

## 一、提交要求

| 项 | 规定 |
|---|---|
| 份数 | 每人 1 份 |
| 命名 | `<角色>-<姓名>.md`，例如 `后端A-张三.md` |
| 篇幅 | 建议 800–1500 字，不要贴代码 |
| 核心 | 写**自己**做了什么、卡在哪、怎么解决 —— 教师会**随机抽测代码讲解**，写虚的会在抽测时暴露 |

---

## 二、写作模板

```markdown
# 个人总结 — <姓名>

- 角色：<PM / 后端 / 前端 / AI / 测试文档>
- 负责模块：<如 m3decision 决策层、static 前端>
- 主要提交：<PR 号列表，或 git log --author 的输出摘要>

## 一、我做了什么（必须具体到模块与功能）
1. <功能点>：<做了什么，遇到什么，怎么解决的>
2. …

## 二、我学到的（挑 2–3 个讲透，不要罗列名词）
### 2.1 <技术点>
<为什么需要它 → 它怎么解决 → 我在哪踩了坑>

### 2.2 <工程/协作点>
…

## 三、AI 如何参与我的工作
| 环节 | 我用了什么 AI | 提示词要点 | 我是怎么验证产出的 |
|------|---------------|------------|--------------------|
|      |               |            |                    |

**AI 出的问题与我的处理**：
1. …
2. …

## 四、反思
- 做得好的：
- 做得不好的（要具体，例如"接口变更没同步文档导致前端返工"）：
- 如果重做一次，我会：
```

---

## 三、可参考的真实素材（写的时候对着这些找自己的部分）

| 素材 | 位置 | 能支撑总结里的哪一部分 |
|---|---|---|
| 我负责的代码 | `git log --author="<姓名>" --oneline --stat` | §一 我做了什么 |
| 我参与的评审 | `docs/meetings/Sprint*-例会记录.md` 的 Code Review 表 | §一 / §四 |
| 我写的测试 | `src/test/java/**`、`tools/*.mjs` | §一 / §二 |
| 我写的文档 | `docs/*.md` 中的对应章节 | §一 |
| 开发中发现的缺陷 | `docs/03-测试文档.md` §二（4 个真实缺陷） | §二 / §三 |
| AI 使用记录 | `docs/AI使用记录.md`、各实验报告 §七 | §三 |

## 四、示例

见 `示例-后端A.md`（**注意：那是示例，展示结构与颗粒度，请勿照抄内容**）。

> ⚠️ 抄袭示例会在两个环节暴露：① 抽测时讲不清不属于自己的代码；
> ② 示例中提到的坑与你的实际经历不符。**写自己的。**
