## 一、我做了什么

1. **能力雷达版本化（核心）**：设计了 `competency_radar` 的版本模型 —— 版本一旦生成即只读，
   任何重算都产生新版本，并把本次计算的**全部输入与权重**写进 `calc_input_json`。
   这样「两时点对比」就退化成两个 `radar_id` 做差，不需要写任何历史回溯逻辑。
   难点是：一开始我打算只存当前值，是 PM 提醒「评委一定会问『你怎么证明画像在动态迭代』」，
   才改成版本化的。

2. **雷达计算公式**：按照架构文档 §6.5 实现加权归一化 + 衰减因子。
   踩的坑是**缺失来源的处理** —— 第一版把缺失来源当 0 分算，导致用户第一次只做测评时，
   「沟通表达」维度直接是 0（因为该维度只有训练评分一个来源）。
   改成「按剩余权重重归一化」后才正确，并补了一个单测把这个行为固定下来。

3. **职业路径生成**：接入 `AiChatPort` 的结构化输出，并实现 SSE 流式返回，
   让用户能看到「分析 → 生成 → 校验 → 落库」的过程，而不是干等。

4. **修了一个安全漏洞**：契约测试报「未登录访问受保护接口应该 401，但实际返回 200」。
   排查发现是 SSE 异步请求不触发 `afterCompletion`，导致 `ThreadLocal` 里的登录态
   被同一线程的后续请求复用。修复方式是在 `preHandle` 里先 `AuthContext.clear()`。
   这件事让我第一次真切意识到**自动化断言和手动点页面的差距**。

## 二、我学到的

### 2.1 「可解释」是一种设计约束，不是一个形容词
做雷达公式时，我本想让模型直接给 8 个维度打分，省事。
但被问了一句「那评委问你为什么是 67.5 分，你怎么答」——
我才明白：**凡是需要对外解释的数字，都不能交给概率模型**。
后来把分值设计成「来源 × 权重」的可复算公式，并把权重表存进 `sys_config` 可以现场改。
答辩时能逐维展开贡献值，这是我认为本项目最有说服力的设计。

### 2.2 版本化让「历史」这件事变简单
不可变 + 版本号 + 快照输入，这三件事组合起来之后：
对比不用查历史表、审计不用重放、回滚不用补偿逻辑。
代价只是表多一列、每次重算多插一批行。

### 2.3 安全结论必须自己验证
`ThreadLocal` 用完 `remove` 看起来天经地义，AI 也回答「这样就不会泄漏」。
但异步请求根本不走 `afterCompletion`。**AI 说没问题不等于没问题**。

## 三、AI 如何参与我的工作

| 环节 | 我用了什么 AI | 提示词要点 | 我是怎么验证产出的 |
|------|---------------|------------|--------------------|
| 公式边界用例 | Claude Code | 「这个加权公式在来源缺失/全 0/全 100 时分别应该是什么结果？列出边界」 | 把 AI 列的 8 个边界写成单测，跑通才算数 |
| 安全审查 | Claude Code | 「这是用 ThreadLocal 存登录态的拦截器，列出所有可能泄漏的路径」 | **写断言**：无 Cookie 请求受保护接口必须 401 → 修复前失败、修复后通过 |
| 代码骨架 | Cursor | 「按 Entity/Mapper/Service 分层写雷达版本的插入逻辑，参数用 #{}」 | 编译 + 启动服务 + 调真实接口看数据 |
| 排障 | Claude Code | 贴报错栈问「这个 H2 的 getKey 报错是什么原因」 | 按建议改 `prepareStatement(sql, new String[]{"id"})` 后实测通过 |

**AI 出的问题与我的处理**：
1. AI 建议雷达公式「缺失来源按 0 分参与加权」—— 我没细想就用了，结果沟通表达维度恒为 0；
   是单测断言「只有训练评分时应等于训练分」把它抓出来的。**教训：数值逻辑必须写断言。**
2. AI 说「ThreadLocal remove 就不会泄漏」—— 不完整。我追问「所有泄漏路径」后才暴露异步请求的问题。
3. AI 生成的 SQL 里用了 `${}` 拼接（可注入）—— 全部改为 `#{}`。

## 四、反思

**做得好的**
- 核心算法（雷达公式）没有图省事交给模型，坚持做成可复算的公式，并配了 10 个单测；
- 遇到「测试说未登录能访问」这种反直觉现象时，没有改测试而是去查根因，最终修掉一个真实漏洞。

**做得不好的**
- 路径生成接口返回结构改过一次，没同步文档，导致前端返工半天。
  后来团队定下「接口变更必须同时更新 `02-需求与设计.md` §六」，但我应该是第一个做到的人；
- 一开始把 `SELECT *` 当成小事，后来意识到它会把 `password_hash` 带进内存，增大了泄漏面。

**如果重做一次**
- 我会先写「未登录 401 / 越权 403 / 缺失来源重归一化」这三条断言，再开始写实现；
- 我会更早地把提示词从 Java 代码里抽出来做成版本化文件 ——
  真实模型一旦上线，提示词会频繁调整，埋在代码里改起来非常痛苦。
