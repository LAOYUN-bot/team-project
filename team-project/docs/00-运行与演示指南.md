# 00 运行与演示指南

> 面向：新成员、答辩演示者、评审老师。
> 目标：**一台干净机器上 3 条命令跑起来**，并且知道该点哪里。

---

## 一、三条命令跑起来

```powershell
cd team-project
.\run.ps1
# 浏览器打开 http://localhost:8080
```

脚本会依次完成：定位 JDK 17 → `mvn -o compile` → 解析依赖 classpath → 启动 Spring Boot。

**为什么不是 `mvn spring-boot:run`？**
本机 Maven 本地仓库缺少 `spring-boot-maven-plugin` 的完整依赖闭包，
因此脚本改为「编译 + classpath 启动」，效果等价且更抗环境差异。
联网环境下 `mvn spring-boot:run` 同样可用。

### 前置条件

| 项 | 版本 | 检查命令 |
|---|---|---|
| JDK | 17 | `java -version`（或设置 `A02_JAVA_HOME`） |
| Maven | 3.9+ | `mvn -v` |
| Node.js | 18+（仅自检脚本需要） | `node -v` |

数据库无需安装：默认 H2 内存库，启动即自动建表并播种。

## 四、常见问题

| 现象 | 原因与处理 |
|---|---|
| 启动报 `Unsupported class file major version 69` | 用了 Java 25。设置 `$env:A02_JAVA_HOME="D:\Java17"` |
| 启动报找不到 `org.apache.maven.plugins:*` 依赖 | 本地仓库缺少该插件版本，执行 `.\run.ps1`（脚本已固定可用版本） |
| 页面能开但数据全空 | 演示数据播种失败，看控制台是否有 `演示数据播种失败`；多为 H2 建表失败 |
| 端口 8080 被占用 | `.\run.ps1 -Port 8081` |
| `mvn test` 失败 | 离线环境缺 surefire provider，改用 README §5 的 `SelfTestRunner` |
| 中文日志在控制台显示为乱码 | 控制台代码页问题，不影响功能；日志文件为 UTF-8 |

## 五、切换到真实大模型（三种方式，改配置不改代码）

```powershell
# 方式 A：本地 Ollama（开发期推荐，零费用无速率限制）
#   1) 安装 Ollama 并拉模型：ollama pull qwen2.5:7b
#   2) 设置 tier=dev，provider=openai
$env:AI_TIER="dev"

# 方式 B：云端 OpenAI 兼容端点（DeepSeek / 通义 / 智谱）
$env:AI_TIER="demo"
$env:DEEPSEEK_API_KEY="你的密钥"
$env:OPENAI_BASE_URL="https://api.deepseek.com/v1"

$env:AI_PROVIDER="openai"   # 或改 application.yml 的 a02.ai.provider
.\run.ps1
```

`OpenAiCompatibleGateway` 已实现：对话、流式、embedding、超时（60s）、
429 限流识别（退避不重试）、5xx/鉴权失败分类、**失败自动降级到本地模板并标记 `degraded=true`**。
切换后用 `GET /api/platform/ai-status` 确认当前 provider、tier、生效模型与降级策略
（界面刻意不暴露模型通道这类运维信息，只给使用者看「使用情况」）。

> 业务代码一行都不用改——这正是「AI 能力走端口 + 统一网关」的价值（NFR-7）。
