## 2. 阻塞原因（真实情况）

赛题要求「依托百宝箱企业版完成智能体开发、配置与多端发布」。当前：

1. **无网络**：本机为完全离线环境，`b.tbox.cn` 与任何外网地址均不可达
   （实测 `registry.npmjs.org` / `repo.maven.apache.org` / `www.baidu.com` 返回 `000`）。
2. **无企业版凭据**：未取得 `TBOX_API_KEY` 与 `TBOX_AGENT_ID`，
   因此 `ai.provider` 运行在 `mock` 通道（架构文档 §7.2 AD-2 的降级设计本就是为此准备的）。
3. **无渠道发布权限**：小程序发布需要在百宝箱控制台绑定渠道并提交审核。

> 这对应需求文档风险项 **R-1「百宝箱权限未下发」**，其应对方案
> （`AiChatPort` 端口 + Mock 实现 + 一键切换）**已在本 Demo 中完整落地并验证**，
> 因此平台权限未到并不阻塞其余全部关键路径。

## 5. 多端一致性设计说明（已完成，供验证时对照）

即便小程序端尚未发布，**保证多端一致的架构决策已经落地**：

| 决策 | 实现 | 位置 |
|---|---|---|
| 会话与画像状态只存后端 | H2/MySQL 是唯一业务真相源，端上无状态 | `docs/04-架构设计.md` §6.1 |
| 智能体侧不存业务状态 | Mock/Tbox 适配器均无状态，上下文每次由后端注入 | `ai/AiService#buildContext` 调用点 |
| 小程序端不重写业务页面 | 计划用百宝箱渠道承接对话入口，业务数据仍回后端 | 架构文档 AD-9 |
| 令牌双通道 | Web 走 HttpOnly Cookie，小程序端走响应体 token（无 Cookie 语义） | `m1perception/AuthController` |

因此两端登录同一账号时，看到的画像版本、学习进度、训练评分必然一致——
因为它们读的是同一份后端数据，不存在端侧缓存导致的漂移。
