# 团队 AI 使用公约

> 课程要求：建立「团队 AI 使用公约」，明确**哪些环节可用 AI、如何标注 AI 产出、如何做人工复核**。
> 本公约经团队成员签署后生效，违反者需在周会上说明。

---

## 一、总则

1. **AI 是生产力工具，不是责任主体。** 所有提交到仓库的代码与文档，最终责任人是团队成员本人。
2. **必须能讲清自己提交的代码。** 教师随机抽测时讲不清的部分，视为未完成的工作量。
3. **关键决策不得外包给 AI。** 架构选型、安全方案、评分算法、合规边界必须人工拍板并留痕。

---

## 二、可以放心用 AI 的环节（✓）

| 环节 | 允许的做法 | 举例 |
|---|---|---|
| 检索与学习 | 问概念、查 API 用法、解释报错 | 「MyBatis 的 `useGeneratedKeys` 在 H2 下怎么写」 |
| 脚手架与样板代码 | 生成重复性结构，人工逐行理解 | Entity / Mapper / Controller 骨架、getter/setter |
| 单元测试用例 | 让 AI 列边界情况，人工判断是否合理 | 「雷达公式的缺失来源重归一化该测哪些边界」 |
| 文案与翻译 | 生成初稿，人工改写 | 这段文档换个更好的说法 |
| SQL 与正则 | 生成后**必须亲自执行验证** | 复杂聚合查询 |
| 代码评审辅助 | 让 AI 做初筛，人工确认 | 「这个 PR 有没有明显的空指针风险」 |
| 前端样式微调 | 生成 CSS，人工在页面确认 | 卡片间距、响应式断点 |

## 三、必须谨慎的环节（⚠ 需二次验证）

| 环节 | 风险 | 强制动作 |
|---|---|---|
| 涉及**数值计算**的代码 | AI 常写「看起来对」的公式 | 必须写单测断言具体数值（本项目的雷达公式有 10 个断言） |
| 涉及**权限与鉴权**的代码 | 漏判等于越权漏洞 | 必须写「未登录 401 / 越权 403」的自动化断言 |
| 涉及**数据访问**的 SQL | 拼错表名/字段，或漏 `deleted=0` | 必须真实调用接口验证（本项目用 53 项接口契约测试） |
| 涉及**流式/异步**的代码 | 线程上下文、异常路径易漏 | 必须构造失败路径验证（如 SSE 断开、模型超时） |
| 配置与依赖版本 | AI 可能给出不存在的版本号 | 必须在真实环境编译通过 |

## 四、绝对禁止（✗）

| 禁止项 | 原因 |
|---|---|
| 把真实个人信息、学号、身份证、手机号贴给 AI | 隐私合规（《个人信息保护法》最小必要原则） |
| 把企业 API Key、数据库密码、JWT 密钥贴给 AI | 密钥泄露，且违反赛题与课程安全要求 |
| 把整模块外包给 AI 后**不复核、不理解**直接提交 | 课程明令禁止：「严禁直接提交 AI 生成的未理解代码」 |
| 用 AI 生成**虚构的实验数据、测试结果、截图** | 学术诚信问题 |
| 用 AI 生成**专利/软著申请书的法律声明部分** | 需要人工承担责任 |

## 五、AI 产出的标注方式

### 5.1 代码标注

AI 参与度较高的代码，在**类注释或方法注释**中说明其角色；对逐行由 AI 生成且未经大改的片段，加行内标记：

```java
// AI-assisted: 由 AI 生成的样板结构，已人工复核字段与边界
public int insert(User user) { ... }
```

### 5.2 提交信息标注

```
feat(m3): 雷达版本化与衰减因子实现

AI 使用：用 AI 生成公式的边界用例，公式本身依据架构文档 §6.5 人工实现
自测：新增 10 个单测，覆盖缺失来源重归一化与 α 衰减
```

### 5.3 PR 模板中标注

`.github/PULL_REQUEST_TEMPLATE.md` 第五节「AI 使用说明」为**必填项**：
勾选是否使用 AI、涉及哪些部分、已标注 `// AI-assisted` 的位置。

### 5.4 文档中标注

- 团队级使用记录：`docs/AI使用记录.md`
- 个人实验报告：每份末尾含「AI 工具使用记录」小节（用了哪些工具、在哪些环节、提示词要点、**产出如何验证**）

## 六、人工复核的最低标准（「三道关」）

任何 AI 产出进入仓库前，必须至少通过：

| 关卡 | 手段 | 本项目实例 |
|---|---|---|
| **第一关：能编译/能跑** | 本地执行 | `mvn -o compile` + `.\run.ps1` 启动成功 |
| **第二关：有断言** | 自动化测试 | 980 项检查（46 单测 + 53 接口 + 868 图表断言 + 13 MCP） |
| **第三关：能讲清** | 口头讲解 | 周会或答辩时，向其他成员解释「这段为什么这么写」 |

> **本项目的实践证据**：开发过程中 AI 参与产出的代码里，共有 **4 个缺陷被上述第二关捕获**
> （含 1 个鉴权上下文泄漏的安全漏洞），全部在提交前修复。详见 `docs/03-测试文档.md` §二。

---

## 七、AI 能力边界的公开声明

在项目文档与产品界面中如实说明 AI 的能力边界，不夸大：

- 界面所有 AI 生成内容均带 **「AI 生成」标识**；面板统一下发 `disclaimer` 文案；
- 雷达分值与匹配度**由本地公式计算，AI 不参与打分**；
- 趋势分析**无来源不外答**；上下文不足时明确说明「知识库中暂无相关信息」；
- 不提供医疗、法律、心理诊断等专业决断类建议。
